## 5. Постановка задачі
Створити консольний Python-застосунок для обліку та аналізу спортивних результатів.

### Вимоги до даних:
Для кожного спортсмена зберігати:
- **ім'я** (`name: str`);
- **вид спорту** (`sport: str`);
- **результат** (`result: float`);
- **категорія** (`category: str`).

### Вимоги до бізнес-логіки:
- Додавання результату;
- Пошук спортсменів за видом спорту;
- Визначення найкращого результату (за видом спорту або серед усіх);
- Обчислення середнього результату;
- Формування рейтингу спортсменів.

### Вимоги до архітектури та оформлення:
- Структура проєкту за принципом `src-layout`;
- Модель даних реалізована за допомогою `dataclass`;
- Розподіл коду на модулі: `models.py` (моделі даних), `services.py` (бізнес-логіка), `main.py` (точка входу);
- Покриття коду анотаціями типів (`type hints`);
- Точка входу захищена конструкцією `if __name__ == "__main__":`;
- Наявність конфігураційного файла `pyproject.toml` та підтримка *editable installation* (`pip install -e .`);
- Наявність файлів `.gitignore` та `README.md`;
- Фіксація розробки в Git щонайменше трьома логічними комітами;
- **Завдання підвищеної складності**: інтерактивне консольне меню (menu-driven interface), введення даних із клавіатури з валідацією, власний клас винятку `InvalidAthleteDataError`, розширений пошук за кількома критеріями, статистика.

   - `calculate_statistics`: збір зведених статистичних показників (кількість, середнє, мінімум, максимум).

4. **`src/sports_tracker/main.py`**:
   Головний виконуваний модуль застосунку:
   - Функції форматованого виведення списків та таблиць (`print_athletes`);
   - Захищене введення з клавіатури з валідацією типів (`prompt_non_empty_string`, `prompt_positive_float`);

## 8. Текст основних фрагментів коду

### 8.1. `src/sports_tracker/models.py`
```python
from dataclasses import dataclass

class InvalidAthleteDataError(ValueError):
    """Raised when athlete data fails validation."""
    pass

@dataclass
class Athlete:
    name: str
    sport: str
    result: float
    category: str

    def __post_init__(self) -> None:
        self.name = self.name.strip()
        self.sport = self.sport.strip()
        self.category = self.category.strip()

        if not self.name:
            raise InvalidAthleteDataError("Athlete name cannot be empty.")
        if not self.sport:
            raise InvalidAthleteDataError("Sport name cannot be empty.")
        if not self.category:
            raise InvalidAthleteDataError("Category cannot be empty.")
        if self.result < 0:
            raise InvalidAthleteDataError(
                f"Result cannot be negative. Received: {self.result}"
            )
```

### 8.2. `src/sports_tracker/services.py`
```python
from sports_tracker.models import Athlete

DEFAULT_PRECISION: int = 2

def add_result(athletes: list[Athlete], athlete: Athlete) -> None:
    athletes.append(athlete)

def filter_by_sport(athletes: list[Athlete], sport: str) -> list[Athlete]:
    target = sport.strip().lower()
    return [a for a in athletes if a.sport.lower() == target]

def find_best_result(
    athletes: list[Athlete],
    sport: str | None = None,
    higher_is_better: bool = True,
) -> Athlete | None:
    candidates = filter_by_sport(athletes, sport) if sport else athletes
    if not candidates:
        return None
    return max(candidates, key=lambda a: a.result) if higher_is_better else min(candidates, key=lambda a: a.result)

def calculate_average_result(athletes: list[Athlete], sport: str | None = None) -> float:
    candidates = filter_by_sport(athletes, sport) if sport else athletes
    if not candidates:
        return 0.0
    return round(sum(a.result for a in candidates) / len(candidates), DEFAULT_PRECISION)

def generate_ranking(
    athletes: list[Athlete],
    sport: str | None = None,
    descending: bool = True,
) -> list[Athlete]:
    candidates = filter_by_sport(athletes, sport) if sport else athletes
    return sorted(candidates, key=lambda a: a.result, reverse=descending)
```

## 9. Пояснення `pyproject.toml`

Файл `pyproject.toml` є сучасним декларативним стандартом конфігурації Python-пакетів згідно з PEP 517, PEP 518 та PEP 621. Він замінює застарілі файли `setup.py` та `setup.cfg`.

Вміст файла:
```toml
[build-system]
requires = ["setuptools>=70"]
build-backend = "setuptools.build_meta"

[project]
name = "sports-tracker"
version = "0.1.0"
description = "Sports results tracking system - Laboratory work 1 for Professional Python"
readme = "README.md"
requires-python = ">=3.11"
authors = [
    { name = "Danylo Harbiсh" }
]
keywords = ["sports", "tracker", "python", "laboratory"]
classifiers = [
    "Programming Language :: Python :: 3",
    "Programming Language :: Python :: 3.11",
    "Programming Language :: Python :: 3.12",
]

[project.scripts]
sports-tracker = "sports_tracker.main:main"
```

### Призначення секцій:
- **`[build-system]`**: Визначає інструмент для збирання пакету (`setuptools`) та бекенд (`setuptools.build_meta`). Це дозволяє менеджеру `pip` коректно зібрати та встановити пакет у будь-якому середовищі.
- **`[project]`**: Містить основні метадані дистрибутива:
  - `name`: назва пакета в системі керування пакетами (`sports-tracker`);
  - `version`: поточна версія проєкту (`0.1.0`);
  - `description`: стислий опис функціональності;
  - `readme`: посилання на файл документації;
  - `requires-python`: обмеження щодо версії інтерпретатора (не нижче 3.11);
  - `authors`: відомості про автора проєкту.
- **`[project.scripts]`**: Реєструє глобальну точку входу (CLI-команду) `sports-tracker`, яка зв'язана з викликом функції `main()` з модуля `sports_tracker.main`. Після встановлення через `pip install -e .` програму можна викликати з консолі просто за іменем команди.

## 15. Відповіді на контрольні запитання

### 1. Що таке Python-проєкт?
**Відповідь:** Python-проєкт — це організована сукупність файлів вихідного коду, модулів, пакетів, файлів конфігурації, залежностей, автоматизованих тестів та документації, що разом утворюють цілісне програмне рішення або бібліотеку.

### 2. Чим проєкт відрізняється від одного Python script?
**Відповідь:** Скрипт — це окремий файл із послідовними інструкціями, призначений для виконання невеликої разової задачі. Проєкт має чітку архітектурну структуру (пакети, модулі), використовує ізольоване віртуальне середовище, систему керування залежностями, стандартизовану збірку (`pyproject.toml`), контроль версій (Git) та документацію, що робить його придатним для масштабування, тестування та командної розробки.

### 3. Що таке Python module?
**Відповідь:** Python-модуль — це звичайний файл із розширенням `.py`, який містить визначення функцій, класів, змінних або виконуваний код і може бути імпортований в інші файли за допомогою інструкції `import`.

### 4. Що таке Python package?
**Відповідь:** Python-пакет — це спеціальна директорія, яка містить один або більше Python-модулів (а також підпакетів) та файл `__init__.py`. Пакети дозволяють організовувати ієрархічний простір імен для коду.

### 5. Для чого потрібний `__init__.py`?
**Відповідь:** Файл `__init__.py` вказує інтерпретатору Python, що каталог є пакетом. Крім того, у ньому можна ініціалізувати стан пакета, задавати версію (`__version__`), обмежувати публічний інтерфейс через `__all__` або налаштовувати зручні скорочені імпорти.

### 6. Що таке src-layout?
**Відповідь:** `src-layout` — це шаблон організації проєкту, за якого весь вихідний код розташовується у підкаталозі `src/` (наприклад, `src/sports_tracker/`), а не безпосередньо у корені репозиторію поруч із конфігураційними файлами.

### 7. Які переваги має src-layout?
**Відповідь:** Головна перевага — запобігання випадковому імпорту незібраного/невстановленого локального коду при запуску тестів із кореня репозиторію. Це гарантує, що застосунок тестується саме так, як він буде встановлений у кінцевого користувача через `pip`, а також спрощує конфігурацію пакувальників і запобігає засміченню кореня файлами байт-коду.

### 8. Для чого використовується virtual environment?
**Відповідь:** Віртуальне середовище (virtual environment) використовується для ізоляції сторонніх бібліотек та залежностей проєкту. Це запобігає конфліктам версій між різними проєктами на одній системі та унеможливлює пошкодження системного інтерпретатора Python.

### 9. Як створити `.venv`?
**Відповідь:** За допомогою стандартного модуля Python:
```bash
python -m venv .venv
```

### 10. Як активувати virtual environment?
**Відповідь:**
- У Windows (PowerShell): `.venv\Scripts\activate`
- У Windows (CMD): `.venv\Scripts\activate.bat`
- У Linux / macOS: `source .venv/bin/activate`

### 11. Для чого використовується pip?
**Відповідь:** `pip` — це офіційний менеджер пакетів для Python, який використовується для пошуку, завантаження, встановлення, оновлення та видалення зовнішніх бібліотек із репозиторію PyPI або з локального коду.

### 12. Чому рекомендується `python -m pip`?
**Відповідь:** Команда `python -m pip` гарантує, що `pip` запускається саме для того екземпляра Python, який викликано в поточній командній оболонці (зокрема, у поточному активованому віртуальному середовищі), усуваючи неоднозначність у системах, де встановлено кілька різних версій Python.

### 13. Для чого потрібний `pyproject.toml`?
**Відповідь:** `pyproject.toml` є сучасним стандартом конфігурації Python-проєктів (PEP 518/621). Він визначає систему збирання проєкту (build system backend), метадані проєкту (назва, версія, залежності, автори) та налаштування для сторонніх інструментів (linter, formatters, test runners).

### 14. Що містить секція `[project]`?
**Відповідь:** Секція `[project]` містить стандартизовані декларативні метадані: назву пакета (`name`), номер версії (`version`), короткий опис (`description`), мінімальну сумісну версію Python (`requires-python`), авторів, залежності (`dependencies`), а також точки входу для консольних команд (`[project.scripts]`).

### 15. Що таке editable installation?
**Відповідь:** Встановлення в режимі редагування (виконується командою `pip install -e .` або `--editable`). За такого встановлення замість копіювання файлів у каталог `site-packages` створюється спеціальне посилання на вихідний каталог проєкту. Це дозволяє вносити зміни у вихідний код і відразу бачити їх дію без повторного перевстановлення пакета.

### 16. Для чого використовується `if __name__ == "__main__":`?
**Відповідь:** Ця конструкція перевіряє, чи файл запущено безпосередньо інтерпретатором (у цьому випадку системна змінна `__name__` набуває значення `"__main__"`), чи він був імпортований як модуль іншим файлом. Це запобігає автоматичному виконанню коду запуску програми при імпорті функцій та класів із цього модуля.

### 17. Що таке Git?
**Відповідь:** Git — це розподілена система контролю версій (DVCS), яка дозволяє відстежувати історію змін у файлах, повертатися до попередніх станів коду, створювати паралельні гілки розробки та ефективно співпрацювати в команді.

### 18. Що таке repository?
**Відповідь:** Репозиторій (repository) — це спеціальне сховище Git (каталог `.git`), яке містить усю історію змін проєкту, набір комітів, гілок, тегів та метаданих, що описують еволюцію файлів у робочому дереві.

### 19. Що таке commit?
**Відповідь:** Коміт (commit) — це збережений у репозиторії знімок (снапшот) стану файлів проєкту в певний момент часу. Кожен коміт має унікальний хеш (SHA-1), автора, дату та повідомлення, що описує суть внесених змін.

### 20. Для чого використовується `git status`?
**Відповідь:** Команда `git status` показує поточний стан робочого каталогу та області індексації (staging area): які файли змінено, які додано до індексу для наступного коміту, а які залишаються невідстежуваними (untracked).

### 21. Для чого `git add`?
**Відповідь:** Команда `git add` додає зміни у файлах із робочого каталогу до області індексації (staging area/index), готуючи їх до включення у наступний коміт.

### 22. Для чого `git commit`?
**Відповідь:** Команда `git commit` фіксує всі проіндексовані зміни у базі даних репозиторію Git, створюючи новий постійний запис в історії змін із відповідним повідомленням.

### 23. Що показує `git log`?
**Відповідь:** `git log` відображає хронологічну історію збережених комітів поточної гілки із зазначенням хешу, автора, дати та тексту повідомлення коміту. Параметр `--oneline` виводить кожен коміт компактно в один рядок.

### 24. Для чого потрібен `.gitignore`?
**Відповідь:** Файл `.gitignore` містить правила та шаблони імен файлів і папок, які Git повинен ігнорувати і не відстежувати. Це захищає репозиторій від потрапляння кешів, бінарних файлів, конфіденційних даних, тимчасових файлів ОС/IDE та віртуальних середовищ.

### 25. Чому `.venv` не потрібно комітити?
**Відповідь:** Віртуальне середовище містить бінарні виконувані файли та копії бібліотек, які займають багато місця і прив'язані до конкретної операційної системи, платформи та абсолютних шляхів на машині розробника. На іншій машині воно не працюватиме коректно. Замість коміту `.venv` зберігають список залежностей у `pyproject.toml` або `requirements.txt`, що дозволяє будь-якому користувачеві відтворити чисте середовище однією командою.

### 26. Для чого потрібний README?
**Відповідь:** Файл `README.md` є візитною карткою проєкту та його базовою документацією. Він пояснює користувачам та іншим розробникам, що робить проєкт, які вимоги необхідні для його запуску, як його встановити, налаштувати, запустити та як користуватися його основними функціями.

### 27. Що таке type hints?
**Відповідь:** Анотації типів (type hints) — це синтаксичні позначення в коді Python (введені в PEP 484), які вказують очікувані типи аргументів функцій, результатів повернення та змінних. Вони покращують читабельність коду, спрощують автодоповнення в IDE та дозволяють проводити статичний аналіз коду на помилки за допомогою інструментів на зразок `mypy`.

### 28. Для чого програму розділяють на modules?
**Відповідь:** Розділення на модулі (модульність) забезпечує структурування коду, спрощує навігацію великим проєктом, запобігає дублюванню коду шляхом повторного використання функцій, знижує зачеплення компонентів (coupling) та полегшує тестування й налагодження.

### 29. Що таке business logic?
**Відповідь:** Бізнес-логіка (business logic) — це ядро програмної системи, яке містить специфічні алгоритми, правила обробки даних, розрахунки та обмеження предметної області проєкту незалежно від того, як користувач взаємодіє із системою (через консоль, web чи графічний інтерфейс).

### 30. Чому потрібно відокремлювати application entry point від business logic?
**Відповідь:** Відокремлення точки входу (інтерфейсу введення/виведення, взаємодії з користувачем) від бізнес-логіки відповідає принципу єдиної відповідальності (Single Responsibility Principle). Це робить функції бізнес-логіки «чистими», незалежними від інтерфейсу користувача, що дозволяє легко покривати їх автоматизованими тестами, змінювати інтерфейс (наприклад, замінити CLI на REST API чи GUI) без переписування обчислювальної логіки.

## 16. Висновок
Під час виконання лабораторної роботи №1 було успішно опановано сучасні стандарти створення професійного Python-проєкту та базові навички роботи із системою контролю версій Git. 

Реалізовано індивідуальний варіант №9 («Облік спортивних результатів») із побудовою структури `src-layout`. Програмний код структуровано за трьома основними модулями: модель даних на базі `dataclass` з валідацією (`models.py`), чиста бізнес-логіка з алгоритмами фільтрації, пошуку екстремумів, статистичного аналізу та рейтингування (`services.py`), а також точка входу з інтерактивним текстовим інтерфейсом (`main.py`).

Створено стандартизований файл конфігурації `pyproject.toml` (PEP 621), налаштовано ізоляцію залежностей у віртуальному середовищі `.venv`, реалізовано інсталяцію в режимі редагування (`pip install -e .`) із реєстрацією консольної команди `sports-tracker`. Налаштовано файл ігнорування `.gitignore` та детальну документацію в `README.md`. Хід розробки зафіксовано за допомогою трьох логічних атомарних комітів у Git. Отриманий каркас проєкту слугує надійним і масштабованим фундаментом для наступних лабораторних робіт курсу.
